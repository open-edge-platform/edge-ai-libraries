# 如何准备模型

引擎只加载已经准备好并存放在本地磁盘上的模型。**引擎在运行时绝不会下载或导出模型。** 本指南列出每个模型的用途及其可选项，并为所有模型给出统一的准备流程。按照本指南操作，即可在一台全新的机器上准备好所需的全部模型。

所有本地模型都位于同一个模型根目录下：

- 本地运行：`data-intelligence-engine/workspace/models`
- Compose 部署：宿主机上的 `data-intelligence-engine/workspace/models`，默认挂载到容器内的 `/workspace/models`；`quickstart.sh` 则会将 workspace 挂载到与宿主机相同的路径，因此容器内看到的是相同的绝对路径
- 自定义：将 `ENGINE_MODEL_ROOT_PATH` 设置为模型根目录。应指向父目录，而不是某个具体模型。如果模型根目录位于容器的 workspace 之外，还需要以相同路径将其挂载到容器中。

引擎根据每个模型配置的模型 ID 推导出它在根目录下的子目录，参见[模型一览](#2-models-at-a-glance)。如果在根目录下找不到某个模型，引擎还会先相对于当前目录查找，并在根目录之后依次在 `MODEL_PATH` 指定的目录和运行用户的 `~/models` 中查找；在每个根目录下，都会先尝试完整的模型 ID 路径，再尝试其最后一段。

## 使用一个脚本准备模型

`data-intelligence-engine/scripts/prepare-models.sh` 会替你执行[第 4 节](#4-prepare-each-model)中的下载和转换步骤，
每一步都在一个用完即弃的引擎容器中运行。它需要 Docker 和已构建好的引擎镜像（参见
[开始之前](#3-before-you-start)的第 1 步）。输出已存在的模型会被跳过，因此可以重复运行。

```bash
cd data-intelligence-engine/scripts
./prepare-models.sh                                  # 多模态操作指南所用到的全部模型
./prepare-models.sh gme reranker                     # 仅准备部分模型
./prepare-models.sh --all --gme-precision int4
```

| 选项 | 取值 | 说明 |
|---|---|---|
| `MODEL...` | `gme`、`reranker`、`media-reranker`、`layout`、`viclip-b`、`viclip-l`、`cosmos-224p`、`whisper`、`bge` | 要准备的模型；默认为 `gme reranker layout viclip-b whisper media-reranker` |
| `--all` | — | 上述全部模型 |
| `--gme-precision` | `int8`（默认）、`int4`、`fp32` | GME 精度 |
| `--video-precision` | `fp16`（默认）、`fp32` | 视频嵌入精度 |
| `HF_MODEL_DIR`（环境变量） | 目录；默认为 `data-intelligence-engine/workspace/hf_models` | 原始模型 |
| `OV_MODEL_DIR`（环境变量） | 目录；默认为 `data-intelligence-engine/workspace/models` | 转换后的模型，即引擎的模型根目录 |
| `ENGINE_IMAGE`（环境变量） | 镜像；默认为 `data-intelligence-engine:latest` | 运行这些工具所用的镜像 |

`HF_ENDPOINT` 和代理相关变量会传入容器。每个模型都按固定的 commit（`--revision`）下载，上游仓库后续的改动不会影响准备出的模型。本指南的其余部分是该脚本所执行的手动流程。

<a id="1-decide-which-models-you-need"></a>
## 1. 确定所需的模型

根据要处理的内容准备相应模型。如果只处理文本文档，一个文档嵌入模型就足够了。

| 内容 | 所需模型 | 说明 |
|---|---|---|
| 文本文档（txt、md、docx，以及带文本层的 PDF 的正文） | 文档嵌入(embedding)：GME（默认）或 BGE | 必需 |
| PDF 中的插图（图文融合向量） | GME + PP-DocLayoutV3 | 由 PP-DocLayoutV3 定位插图。没有它时，PDF 仅按文本处理 |
| 扫描版 PDF（无文本层） | PP-DocLayoutV3 + 文档嵌入 | 版面区域通过 Tesseract OCR 识别，镜像中已包含 Tesseract |
| 图像 | GME | 与文档嵌入共用同一个 GME 模型包 |
| 短视频（≤ 60 秒） | ViCLIP-B（默认）、ViCLIP-L 或 Cosmos-224p | 每个片段采样八帧；更长的视频会被存储但不做嵌入 |
| 音频 | Whisper + GME | Whisper 负责转写；GME 对转写文本做嵌入 |
| 对检索结果重排(reranking)（默认） | Qwen3-VL-Reranker-2B | 可选。仅在请求带有 `postprocess` 时使用；对文档文本、插图、图像、视频和音频统一打分；参见[文本到媒体检索](../../text-to-media-retrieval.md) |
| 使用纯文本模型对文档文本重排 | bge-reranker-large | 可选。在请求选择该模型或 `ENGINE_RERANK_MODEL_ID` 指向它时使用 |

<a id="2-models-at-a-glance"></a>
## 2. 模型一览

| 模型 | 用途 | 后端（`embedding_backend`） | 模型根目录下的默认目录 | 可选项 | 默认精度 | 大小（约） |
|---|---|---|---|---|---|---|
| GME-Qwen2-VL-2B（OpenVINO 模型包） | 用于文档、PDF 插图、图像和音频转写文本的嵌入，1536 维 | `local_openvino`（GME 运行时） | `gme-Qwen2-VL-2B-Instruct-OV/` | 精度 `int8`（默认）/ `int4` / `fp32` | INT8 | 下载 8.3 GB；模型包 int8 为 2.1 GB，int4 为 1.3 GB |
| BGE（例如 `BAAI/bge-small-en-v1.5`） | 替代 GME 的纯文本嵌入，384 维 | `local_openvino` | `bge-small-en-v1.5/`（模型 ID 的最后一段） | 转换时的 `--weight-format` | FP32 | 约 130 MB |
| bge-reranker-large | 对检索结果重排 | `local_openvino` 或 `remote_openai_compatible` | `BAAI/bge-reranker-large/`（保留厂商目录） | 转换时的 `--weight-format`；或使用远程重排服务 | FP32 | fp32 为 2.2 GB，int8 约 0.6 GB |
| Qwen3-VL-Reranker-2B | 对视频、图像和音频转写文本命中结果进行统一重排 | `local_openvino`（固定） | `Qwen3-VL-Reranker-2B-INT8-OV/` | 无（使用脚本默认值） | INT8（仅权重量化） | 下载 4.2 GB；INT8 模型包约 6 GB（三个计算图）；FP16 导出为中间产物，量化后即删除 |
| PP-DocLayoutV3（ONNX） | PDF 版面检测：插图位置、扫描页区域 | `local_openvino`（固定） | `PP-DocLayoutV3/` | 无 | FP32 | 250 MB |
| Tesseract OCR（内置于镜像） | 扫描版 PDF 区域的文字识别 | 不适用（OCR，而非嵌入） | 位于引擎镜像中，不在模型根目录下 | 简体中文 + 英文（`chi_sim+eng`，固定） | 不适用 | 识别权重 6.6 MB；包含方向与文字脚本检测数据时共 17.1 MB |
| ViCLIP-B（默认） | 短视频嵌入，512 维 | `local_openvino` | `viclip-b-fp16/` | `fp16`（默认）/ `fp32` | FP16 | 取决于精度 |
| ViCLIP-L | 短视频嵌入，768 维 | `local_openvino` | `viclip-l-fp16/` | `fp16`（默认）/ `fp32` | FP16 | 取决于精度 |
| Cosmos-224p（可选） | 短视频嵌入，256 维 | `local_openvino` | `cosmos-224p-fp16/` | `fp16`（默认）/ `fp32` | FP16 | 取决于精度 |
| Whisper `openai/whisper-small` | 语音识别 | `local_openvino`（固定） | `whisper-small/` | 转换时的 `--weight-format` | FP32 | 约 1 GB |

**后端和模型是分开设置的。** 后端（`embedding_backend`：`local_openvino` 或 `remote_openai_compatible`）只表示模型在哪里运行；具体运行时由模型决定。模型本身由 `embedding_model` 指定（一个已准备好的模型 ID，例如 `viclip-b-fp16`），即模型根目录下的目录名。有两个地方可以设置它们：

- 引擎级默认值：`ENGINE_*_EMBEDDING_*` 及相关环境变量；参见第 4 节中各模型的说明。
- 单个数据源：创建数据源时的 `operator_options`，它会覆盖默认值。

每个模型都有一个 `*_DEVICE` 变量，默认值均为 `GPU`（Intel GPU）。在没有 GPU 的主机上，请将它们设置为 `CPU`；`quickstart.sh --cpu` 会为 `deployment/docker/.env` 中尚未设置的每个 `*_DEVICE` 写入 `CPU`；在没有 `/dev/dri` 的主机上，除非设置了 `ENGINE_GPU_DEVICE`，`quickstart.sh` 也会这样做。所有变量都列在[引擎用户指南中的配置](../../user-guide.md#configuration)一节。

默认精度指的是已准备模型存储权重的方式。在 GPU 上，OpenVINO 默认以 FP16 运行 FP32 权重；在不支持 BF16 的 CPU 上，FP32 模型以 FP32 运行。

<a id="3-before-you-start"></a>
## 3. 开始之前

以下所有命令都在仓库的 `data-intelligence-engine/` 目录下、在同一个终端中运行。第 4 节的命令会用到此处设置的两个变量；如果打开了新终端，需要重新设置。

1. **构建引擎镜像。** 参见[快速入门中的第 1 步：部署](../快速开始.md#step-1-deploy)。镜像中已包含 `hf`、`optimum-cli`、PyTorch 和 OpenVINO，因此准备模型只需要 Docker，宿主机上无需安装任何 Python 包。下面的每条命令都在一个用完即弃的容器中运行，不会改动镜像。使用仓库中转换脚本的命令会将当前目录以只读方式挂载到容器内的 `/engine`。

2. **设置两个模型目录。**

   ```bash
   export HF_MODEL_DIR=$PWD/workspace/hf_models   # 原始模型：从 Hugging Face 下载的检查点
   export OV_MODEL_DIR=$PWD/workspace/models      # OV 模型：引擎读取的模型根目录
   mkdir -p "$HF_MODEL_DIR" "$OV_MODEL_DIR"
   [ "$(id -u)" = 1000 ] || sudo chown 1000:1000 "$HF_MODEL_DIR" "$OV_MODEL_DIR"
   ```

   - `OV_MODEL_DIR` 必须是引擎读取的模型根目录。对于 Compose，即 `data-intelligence-engine/workspace/models`。如果放在其他位置，请将 `ENGINE_MODEL_ROOT_PATH` 设置为该目录，并将其挂载到引擎容器中。
   - `HF_MODEL_DIR` 仅在准备过程中使用。全部转换完成后可将其删除以释放磁盘空间。
   - 下面手动执行的准备容器以镜像内的用户（UID 1000）写入文件（`prepare-models.sh` 则以你的用户运行它们）。如果宿主机 UID 不是 1000，最后一行会把两个目录的所有权交给 UID 1000。

3. **网络。** 下载命令会把宿主机的 `HF_ENDPOINT`、`http_proxy`、`https_proxy` 和 `no_proxy` 传入容器；未设置的变量会被忽略。如果无法访问 Hugging Face，请先设置镜像站：

   ```bash
   export HF_ENDPOINT=https://hf-mirror.com
   ```

## 4. 逐个准备模型

<a id="41-gme-documents-images-and-audio-transcripts"></a>
### 4.1 GME：文档、图像和音频转写文本

<a id="1-download-the-original-model"></a>
#### 1. 下载原始模型

```bash
docker run --rm -e HF_ENDPOINT -e http_proxy -e https_proxy -e no_proxy \
  -v "$HF_MODEL_DIR:/hf" --entrypoint hf data-intelligence-engine:latest \
  download Alibaba-NLP/gme-Qwen2-VL-2B-Instruct --revision 9cfa6413f704a7c1cf5064d240748e10c876b286 \
  --include "*.json" --include "*.safetensors" --include "merges.txt" \
  --local-dir /hf/gme-Qwen2-VL-2B-Instruct
```

<a id="2-convert-to-openvino"></a>
#### 2. 转换为 OpenVINO

```bash
docker run --rm -e http_proxy -e https_proxy -e no_proxy -e ENGINE_WORKSPACE=/tmp \
  -v "$HF_MODEL_DIR:/hf:ro" -v "$OV_MODEL_DIR:/ov" -v "$PWD:/engine:ro" \
  --entrypoint sh data-intelligence-engine:latest -c '
    set -e
    # 转换需要 Transformers 5.10（镜像固定为 5.5）；它只安装在这个用完即弃的容器中
    pip install --user -q --no-warn-script-location "transformers==5.10.4"
    cd /engine && PYTHONPATH=src python scripts/export_gme_ov.py \
      --checkpoint /hf/gme-Qwen2-VL-2B-Instruct --precision int8 \
      --output-dir /ov/gme-Qwen2-VL-2B-Instruct-OV
  '
```

<a id="3-output-directory-and-options"></a>
#### 3. 输出目录和选项

输出目录：`$OV_MODEL_DIR/gme-Qwen2-VL-2B-Instruct-OV/`，包含 `gme_openvino_config.json`、`gme_language_<precision>.xml/.bin`、`gme_visual_<precision>.xml/.bin`，以及分词器(tokenizer)和处理器(processor)文件。如果你已有 GME 模型包，将其复制到该目录并跳过第 1、2 步即可。

| 选项 | 取值 | 说明 |
|---|---|---|
| `--precision`（转换） | `int8`（默认）、`int4`、`fp32` | int4 速度最快，精度略低；fp32 精度最高，速度最慢 |
| `--output-dir`（转换） | 目录 | 若目录已存在则拒绝执行 |
| `ENGINE_DOC_EMBEDDING_BACKEND` | `local_openvino`（默认） | 文档嵌入的后端；GME 模型包运行在 GME 运行时上 |
| `ENGINE_DOC_EMBEDDING_MODEL_ID` | `gme-Qwen2-VL-2B-Instruct-OV`（默认） | 模型根目录下的模型包目录名 |
| `ENGINE_DOC_EMBEDDING_DEVICE` | `GPU`（默认）、`CPU` | 文档嵌入使用的设备 |
| `ENGINE_IMAGE_EMBEDDING_BACKEND` | `local_openvino`（默认） | 图像嵌入的后端 |
| `ENGINE_IMAGE_EMBEDDING_MODEL_ID` | `gme-Qwen2-VL-2B-Instruct-OV`（默认） | 模型根目录下的模型包目录名 |
| `ENGINE_IMAGE_EMBEDDING_DEVICE` | `GPU`（默认）、`CPU` | 与文档嵌入使用同一设备时，两者共享同一个运行时 |
| `operator_options.embedding_model`（图像数据源） | 单独准备的 GME 模型包 ID | 通过模型 ID 选择权重变体；不接受 `operator_options.precision` |
| `operator_options.max_image_tokens`（图像数据源） | 整数；默认为模型包的 `processor.max_image_tokens` | 每张图像的视觉 token 上限；是影响延迟的最大因素 |

<a id="47-qwen3-vl-reranker-2b-unified-media-reranking"></a>
### 4.7 Qwen3-VL-Reranker-2B：统一媒体重排

每种模式（`text`、`image`、`video`）各导出一个仅含前向推理的 OpenVINO 计算图。text 模式用于对音频转写文本打分。最终只保留 INT8 仅权重量化(weight-only quantization)的模型包：FP16 导出是中间产物，量化后即被删除。重排器的使用方式参见[文本到媒体检索](../../text-to-media-retrieval.md)。

<a id="1-download-the-original-model-6"></a>
#### 1. 下载原始模型

```bash
docker run --rm -e HF_ENDPOINT -e http_proxy -e https_proxy -e no_proxy \
  -v "$HF_MODEL_DIR:/hf" --entrypoint hf data-intelligence-engine:latest \
  download Qwen/Qwen3-VL-Reranker-2B --revision 4bd860ac4f15ad1897a214615cccc700f8f71818 \
  --include "*.json" --include "*.safetensors" --include "merges.txt" --include "*.jinja" \
  --local-dir /hf/Qwen3-VL-Reranker-2B
```

<a id="2-convert-to-openvino-5"></a>
#### 2. 转换为 OpenVINO

在一个容器中将三种模式全部导出到一个临时 FP16 目录（中间产物，量化后删除）。任何媒体文件都可以作为追踪(trace)样本：视觉输入会被归一化到固定网格，视频对会被填充到同一个序列分桶，因此追踪得到的形状与样本无关。下面的命令会为此合成一张小图像和一个小视频片段。

```bash
docker run --rm -v "$HF_MODEL_DIR:/hf:ro" -v "$OV_MODEL_DIR:/ov" -v "$PWD:/engine:ro" \
  --entrypoint sh data-intelligence-engine:latest -c '
    set -e
    python - <<PY
import cv2, numpy as np
from PIL import Image
Image.new("RGB", (64, 64), (120, 80, 40)).save("/tmp/sample.png")
writer = cv2.VideoWriter("/tmp/sample.mp4", cv2.VideoWriter_fourcc(*"mp4v"), 5, (64, 64))
for i in range(12):
    writer.write(np.full((64, 64, 3), i * 20, np.uint8))
writer.release()
PY
    for mode in text image video; do
      sample=
      [ "$mode" = image ] && sample=/tmp/sample.png
      [ "$mode" = video ] && sample=/tmp/sample.mp4
      python /engine/scripts/export_qwen3_vl_reranker_ov.py \
        --source /hf/Qwen3-VL-Reranker-2B --output /ov/.qwen3-vl-reranker-fp16 \
        --mode "$mode" ${sample:+--sample "$sample"}
    done
  '
```

<a id="3-quantize-to-int8-and-remove-the-fp16-export"></a>
#### 3. 量化为 INT8 并删除 FP16 导出

INT8 可将模型大小减半。从临时 FP16 模型包量化(quantization)到服务目录，然后删除 FP16 目录——
`$OV_MODEL_DIR` 下只保留 INT8 模型包：

```bash
docker run --rm -v "$OV_MODEL_DIR:/ov" -v "$PWD:/engine:ro" \
  --entrypoint python data-intelligence-engine:latest \
  /engine/scripts/quantize_qwen3_vl_reranker_int8.py \
  --src /ov/.qwen3-vl-reranker-fp16 --dst /ov/Qwen3-VL-Reranker-2B-INT8-OV
rm -rf "$OV_MODEL_DIR/.qwen3-vl-reranker-fp16"
```

`prepare-models.sh media-reranker` 会执行全部三个步骤，并自动清理 FP16 目录，
即使失败时也会清理。

<a id="4-output-directory-and-options"></a>

服务目录：`$OV_MODEL_DIR/Qwen3-VL-Reranker-2B-INT8-OV/`，包含 `reranker_text.xml/.bin`、`reranker_image.xml/.bin`、`reranker_video.xml/.bin`、`export_shapes.json` 以及处理器文件。

|---|---|---|
| `ENGINE_MEDIA_RERANK_BACKEND` | `local_openvino`（默认） | 后端（唯一支持的取值） |

<a id="5-check-that-the-models-are-ready"></a>
## 5. 检查模型是否就绪

准备完成后，`$OV_MODEL_DIR` 的结构如下：

```text
$OV_MODEL_DIR/
├── gme-Qwen2-VL-2B-Instruct-OV/       gme_openvino_config.json、gme_language_int8.xml/.bin、gme_visual_int8.xml/.bin、分词器文件
├── BAAI/bge-reranker-large/           openvino_model.xml/.bin、分词器文件
├── Qwen3-VL-Reranker-2B-INT8-OV/      reranker_{text,image,video}.xml/.bin、export_shapes.json、处理器文件（仅权重 INT8）
├── PP-DocLayoutV3/                    pp_doclayout_v3.onnx、id2label.json、preprocessor_config.json
├── viclip-b-fp16/                    video_embedding.json、video_encoder.xml/.bin、text_encoder.xml/.bin、分词器资源
├── viclip-l-fp16/                    相同的模型包布局，768 维（可选）
├── viclip-b-fp32/                    同属 ViCLIP-B 系列，fp32 精度（可选）
├── viclip-l-fp32/                    同属 ViCLIP-L 系列，fp32 精度（可选）
└── whisper-small/                     openvino_encoder_model.xml/.bin、openvino_decoder_model.xml/.bin、config.json、处理器文件
```

引擎运行后，可通过模型发现 API 查看它识别出了哪些模型。`ready: true` 表示推理所需的文件已完整：

```bash
for t in embedding multimodal asr reranker; do
  echo "== $t"; curl -s "http://localhost:16022/v1/models/$t" | jq -c '.models[] | {name, ready}'
done
```

模型实际是在数据源挂接(attach)到池(pool)时才被加载的，因此问题会在此时暴露，早于任何数据摄取。如果某个模型有问题，挂接请求会失败并附带原因：模型文件缺失或无法加载时返回 `503`，模型包或源选项无效时返回 `400`：

| 错误 | 原因 |
|---|---|
| `No prepared OpenVINO ... at ...` | 缺少 `openvino_model.xml/.bin` 或分词器文件。请重新转换，并将结果放到报错中给出的路径 |
| `No exported GME OpenVINO package at ...` | 目录中没有 `gme_openvino_config.json`，或它嵌套超过一层 |
| `GME precision 'x' is incomplete ...` | 缺少所请求精度的 XML/BIN 文件 |
| `... ships [...] and its default_precision ... is not among them` | GME 模型包含有多种精度，但其中没有默认精度。只保留一种精度的文件 |
| `Cannot identify embedding_model ... as a supported media model` | 该目录既不是已准备的视频模型包，也不是 GME 模型包 |
| `No prepared <model> model at ...` | 已识别出该模型包，但内容不完整；错误信息中附有详细说明 |
| 视频清单(manifest)或产物校验错误 | 检查 `video_embedding.json`、根目录下的两组 IR 文件对以及分词器资源；仅有源检查点并不构成运行时模型包 |
| `frames_per_clip=N does not match ...` | 数据源的帧数与视频模型包固定的八帧不一致 |

每个数据源在创建时都会在其 `profile` 中记录所使用的模型；可通过 `curl -s http://localhost:16022/v1/libraries/<library>/sources | jq '.[].profile'` 查看。之后移动模型目录或更改默认值，不会改变已有数据源所记录的内容。

<a id="6-what-you-do-not-need-to-prepare"></a>
## 6. 无需准备的内容

- **OCR**：Tesseract 及其英文（`eng`）和简体中文（`chi_sim`）语言数据已包含在引擎镜像中；无需额外下载或转换 OCR 模型。在当前搭载 Tesseract 5.5.0 的镜像中，默认识别权重总计约 **6.6 MB**：`eng.traineddata` 为 **4.1 MB**，`chi_sim.traineddata` 为 **2.5 MB**。镜像中还包含用于方向与文字脚本检测的 `osd.traineddata`（**10.6 MB**），三个训练数据文件合计约 **17.1 MB**。这些是磁盘上的权重大小（1 MB = 1,000,000 字节），并非运行时内存或 Docker 镜像总大小；它们可能随打包的语言数据而变化。这些文件位于镜像内的 `/usr/share/tesseract-ocr/5/tessdata/`，不在引擎的模型根目录下。
- **分词器词表**：用于统计分块(chunk) token 数的 `cl100k_base` 词表随 LlamaIndex 一起安装，通常无需准备。如果你的安装中缺少它，请在可联网的机器上构建缓存，复制到运行主机，并为引擎进程设置相同的 `TIKTOKEN_CACHE_DIR`：

  ```bash
  TIKTOKEN_CACHE_DIR=/path/to/tokenizer-cache \
    python -c 'import tiktoken; tiktoken.get_encoding("cl100k_base")'
  ```

  缓存缺失或损坏时会以准备错误失败；引擎绝不会自行获取它。
- **视频字幕描述**：由外部视频摘要服务提供；请设置 `ENGINE_VIDEO_SUMMARY_BASE_URL`。未设置时会跳过字幕描述生成，嵌入不受影响。
- **OKF 抽取**：使用外部 LLM 服务；参见 [OKF extractor](../../../../tools/okf_extractor/README.md)。
