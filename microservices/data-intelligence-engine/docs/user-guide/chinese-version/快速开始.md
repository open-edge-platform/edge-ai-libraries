<a id="get-started"></a>
# 快速入门

- **完成时间：** 约 25 分钟，大部分时间用于首次下载模型

部署 Data Intelligence Engine 与 Milvus，摄取(ingest)一个文本文件，并对其进行检索。

<a id="prerequisites"></a>
## 前提条件

- Docker 及 Docker Compose v2（[安装指南](https://docs.docker.com/engine/install/ubuntu/)）、
  `curl` 和 `jq`。
- 约 50 GB 可用磁盘空间，用于存放镜像、所有默认模型及其下载的原始文件（原始文件之后可以删除）；
  使用 `--models`（见步骤 1）时所需空间更少。
- 首次运行时需要能够访问 Hugging Face。如果处于代理之后，请导出
  `http_proxy`/`https_proxy` 并配置 Docker 守护进程的代理。位于中国大陆的用户
  可能需要设置 `export HF_ENDPOINT=https://hf-mirror.com`。

DOCX/PPTX 文件中的 WMF/EMF 图片使用 LibreOffice 渲染，Docker 镜像中已包含 LibreOffice。
如需在不包含它的情况下构建，请在首次运行前（或在重新构建镜像前）导出
`INSTALL_LIBREOFFICE=false`；此时这些图片会被跳过，文件的其余部分仍会被摄取。
在 Debian/Ubuntu 上原生安装时需要 `libreoffice-draw-nogui` 和 `fonts-dejavu-core`。

如果你是从较大的 monorepo 克隆，并且只需要此服务，可以使用稀疏检出(sparse checkout)：

```bash
git clone --filter=blob:none --sparse https://github.com/open-edge-platform/edge-ai-libraries.git
cd edge-ai-libraries
git sparse-checkout set microservices/data-intelligence-engine
cd microservices/data-intelligence-engine
```

<a id="step-1-deploy"></a>
## 步骤 1：部署

```bash
bash scripts/quickstart.sh
```

首次运行会构建镜像，在 `workspace/models` 下下载并准备**所有**默认模型
（GME、bge-reranker-large、PP-DocLayoutV3、ViCLIP-B、Whisper 以及 Qwen3-VL
INT8 媒体重排(reranking)模型），在端口 `16022` 上启动 Milvus 和引擎，
并将 Milvus 注册为 `local-milvus`。之后的运行只会启动服务。

**GPU 还是 CPU。** 默认所有模型都运行在 Intel GPU（`/dev/dri`）上。传入 `--cpu`
可让所有模型改为在 CPU 上运行；没有 `/dev/dri` 的主机会自动回退到 CPU。该选择会以
`ENGINE_*_DEVICE=CPU` 的形式写入 `deployment/docker/.env`，文件中已有的值会保留。

**工作区路径。** `quickstart.sh` 会将 `workspace/` 以其宿主机路径挂载到引擎中
（`deployment/docker/.env` 中的 `ENGINE_WORKSPACE_HOST_PATH`/`ENGINE_WORKSPACE_CONTAINER_PATH`），
因此存储的 `file_path` 和 `media_key` 值都是宿主机上其他智能体(agent)可以直接打开的真实路径。
引擎以你的用户身份运行（`USER_UID`/`USER_GID`）。摄取之后不要更改这些路径；如果更改了，需要重新摄取。

如果你不需要所有模型，可以在首次运行时通过 `--models` 指定要准备的模型。
本指南中的文本摄取和检索只需要 GME，它同时为文件和查询生成嵌入(embedding)，
因此下面的命令就足以运行后续所有步骤：

```bash
bash scripts/quickstart.sh --models "gme"
```

之后在摄取 PDF、图片、视频或音频时，再使用 `scripts/prepare-models.sh` 准备其他模型。

镜像只在缺失时才会构建，因此修改引擎源码后需要重新构建；引擎容器会基于新镜像重新创建。
如需停止并移除服务（保留数据和模型），请使用 `--down`。运行
`bash scripts/quickstart.sh --help` 查看其他选项。

```bash
bash scripts/quickstart.sh --build
bash scripts/quickstart.sh --down
```

检查引擎状态：

```bash
cd scripts
./status.sh health
```

```json
{
  "service": "engine",
  "status": "ok",
  "workspace": "/path/to/data-intelligence-engine/workspace",
  "databases": 1,
  "asset_libraries": 0
}
```

<a id="databases"></a>
### 数据库

数据库连接在运行时通过 API 注册，而不是在配置文件中设置。本指南本身无需进行任何注册：

- `quickstart.sh` 已将 Milvus 注册为 `local-milvus`
  （`http://milvus-standalone:19530`）；这就是上面的 `"databases": 1`，
  步骤 2 中的数据源会使用它。
- 首次摄取会注册 `workspace-content`，这是位于 `workspace/content` 下的文件系统存储，
  用于保存已摄取的内容。

使用 `./databases.sh read` 列出已注册的连接。每种后端接受以下 `options`：

| `type` / `backend` | `options`，其中地址为引擎容器所见的地址 |
|---|---|
| `vector` / `milvus` | `uri`（必填），例如 `http://milvus-standalone:19530`；其他键（如 `token` 或 `db_name`）会传递给 Milvus 客户端 |
| `graph` / `nebula` | `url`（必填），例如 `nebula://nebula-graphd:9669`；可选 `username`（默认 `root`）、`password` 和 `space` |
| `object` / `filesystem` | `root`（必填），容器内的一个目录，例如 `<workspace>/content`（即宿主机工作区路径，见步骤 1） |

<a id="step-2-ingest-a-file"></a>
## 步骤 2：摄取文件

编写一个示例文件：

```bash
cat > /tmp/edge-notes.txt <<'EOF'
Intel Edge AI Libraries provide microservices for building AI applications at the edge.
The Data Intelligence Engine ingests documents, images, videos and audio, embeds them
with OpenVINO models, stores the vectors in Milvus and serves retrieval over HTTP.
EOF
```

创建一个库(library)、一个使用默认文本模型索引到 Milvus 的数据源(source)，
以及一个将二者绑定的池(pool)；然后摄取该文件。`--wait` 会在文件索引完成后返回：

```bash
./library.sh create '{"name":"demo"}'
./sources.sh create demo '{"name":"docs","database_id":"local-milvus","collection_name":"demo_docs"}'
./pools.sh create demo '{"id":"docs","name":"Docs","sources":["docs"]}'
./assets.sh add demo /tmp/edge-notes.txt --pool docs --wait
```

如需摄取更多类型的文件（PDF、图片、视频、音频或 OKF 知识包），请参阅
[如何摄取多模态数据](how-to-guides/如何导入多模态数据.md)。

<a id="step-3-retrieve"></a>
## 步骤 3：检索

```bash
./retrieve.sh query demo "Where are the vectors stored?" --pool docs --top-k 3 \
  | jq '.chunks[] | {score, file: .metadata.file_name, text}'
```

示例结果：

```json
{
  "score": 0.24457761645317078,
  "file": "edge-notes.txt",
  "text": "Intel Edge AI Libraries provide microservices for building AI applications at the edge.\nThe Data Intelligence Engine ingests documents, images, videos and audio, embeds them\nwith OpenVINO models, stores the vectors in Milvus and serves retrieval over HTTP."
}
```

如果不使用 `jq` 过滤，每个分块(chunk)还会携带其 `metadata`（资产、数据源、池和排名）。
相同的搜索也可以通过 `POST /v1/retrieve` 完成；位于
[http://localhost:16022/console/](http://localhost:16022/console/) 的 Web 控制台同样可以执行该搜索。
