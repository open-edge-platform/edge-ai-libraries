Metrics Manager release "{{ .Release.Name }}" is configured in namespace "{{ .Release.Namespace }}".

Workload kind: {{ .Values.controller.kind }}
Image:         {{ include "metrics-manager.image" . }}
Privileged:    {{ or .Values.hardware.telemetry.enabled .Values.securityContext.privileged }}
Host PID:      {{ or .Values.hardware.telemetry.enabled .Values.pod.hostPID }}
GPU collector: {{ and .Values.hardware.telemetry.enabled .Values.hardware.gpu.enabled }}

This does not confirm telemetry readiness. Verify the pods and metric families below.
For RC validation set image.tag=2026.3.0-rc1 or 2026.3.0-extended-rc1.

1. Verify pods are running:

   kubectl --namespace {{ .Release.Namespace }} get pods -l app.kubernetes.io/instance={{ .Release.Name }}

2. Open a port-forward to the REST API + SSE:

   kubectl --namespace {{ .Release.Namespace }} port-forward svc/{{ include "metrics-manager.fullname" . }} {{ .Values.service.metricsPort }}:{{ .Values.service.metricsPort }}

   Then check health:
     curl http://localhost:{{ .Values.service.metricsPort }}/health

3. Open a port-forward to the Telegraf Prometheus endpoint:

   kubectl --namespace {{ .Release.Namespace }} port-forward svc/{{ include "metrics-manager.fullname" . }} {{ .Values.service.telegrafPort }}:{{ .Values.service.telegrafPort }}

   Then scrape:
     curl http://localhost:{{ .Values.service.telegrafPort }}/metrics | head

4. For upgrades from 2026.2.0, migrate old collector values and custom Telegraf
   configuration first. Do not use --reuse-values. Native metrics use new names
   and base units; follow the migration guide before upgrading dashboards.
